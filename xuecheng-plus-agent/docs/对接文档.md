# 学成在线门户 AI 助手 · Java 侧对接文档

> 本文档面向学成在线 Java 工程（Spring Boot），说明接入 AI 助手模块所需的全部改造点。
> 核心原则：**AI 模块独立部署，Java 侧仅需新增少量接口，不改动原有业务核心代码。**

---

## 0. 交互总览

| 交互点 | 方向 | 说明 |
|---|---|---|
| 1. 门户入口跳转 | Java → 前端 | 首页导航栏新增"AI学习助手"按钮，携带 JWT 跳转 AI 页面 |
| 2. JWT 密钥共享 + 画像解析 | 双向 | Java 签发 HS256 JWT；AI 服务本地校验并解析 `user_name` 用户画像 |
| 3. 讲义上传 + MQ 消息 | Java → RabbitMQ → AI | 教学机构端上传讲义至 MinIO，发消息通知 AI 异步解析 |
| 4. 解析状态回调 | AI → Java | AI 处理完讲义后调用 Java 接口更新讲义状态 |
| 5. 解析状态查询 | AI → Java | media-api 提供按课程查询解析状态的接口（agent 转发） |
| 6. 课程信息查询 | AI → Java | Agent 调用公开课程列表接口做课程推荐 |
| 7. 我的课程查询 | AI → 网关 → learning | agent 携带用户原始 JWT 经网关透传调用 `/learning/mycoursetable` |
| 8. 课程详情跳转 | 前端 → 门户 | 回答中的课程卡片链接指向门户课程详情页 |

## 1. 门户入口跳转（首页导航栏）

在门户首页导航栏新增按钮，登录后携带 JWT token 跳转至 AI 助手页面（AI 服务地址由配置项指定）。

**模板页面**（`portal/index.html` 或对应 Thymeleaf 模板）:

```html
<!-- 登录后展示 -->
<a th:if="${loginUser != null}"
   th:href="@{'http://<AI服务地址>/index.html?token=' + ${jwtToken}}"
   target="_blank" class="nav-link">AI 学习助手</a>
```

> 说明：`jwtToken` 为门户登录后生成的 JWT（与 AI 服务共享密钥）。若门户使用
> Spring Security + JWT 过滤器，可在请求上下文或 Redis 中取出当前用户 token。
> token 也可以存于前端 localStorage，由前端在跳转时拼接，AI 页面将 token 保存后调用接口。

**JWT 约定**（必须与 AI 服务 `JWT_SECRET` / `JWT_ALGORITHM` 一致，HS256）：

```json
{
  "sub": "52",
  "user_name": "{\"id\":\"52\",\"username\":\"stu1\",\"name\":\"学生一\",\"nickname\":\"阿明\",\"utype\":\"101002\"}",
  "aud": "xuecheng-plus",
  "iat": 1730000000,
  "exp": 1730086400
}
```

- **用户身份在 `user_name`（XcUserExt 用户对象的 JSON 字符串）**：AI 服务解析其中的 `id / username / name / nickname / utype`，注入系统提示（显示名优先级：昵称 > 姓名 > 用户名）。
- **兼容早期格式**：`sub / user_id / uid / userId` 直接携带用户 ID 的 JWT 也能解析（此时仅能取得用户 ID）。
- `aud` 字段 AI 侧校验时忽略（`verify_aud=False`），兼容门户 JWT。

AI 服务校验逻辑：本地 `HS256 + 共享密钥` 解码 → 校验过期/签名 → 解析画像，不调用 Java 远程接口；每个请求**单次解码**同时产出用户 ID / 原始 token / 画像（`get_auth_context`）。

## 2. 教学机构端：讲义上传接口（含 MQ 通知）

**改造点 A：讲义上传/重新上传接口**

1. 讲义文件上传至 MinIO（bucket 建议 `lecture`，路径建议 `{courseId}/{yyyyMMdd}/{fileId}.{ext}`）
2. 讲义解析状态表新增记录，初始状态 `processing`
3. 发送 RabbitMQ 消息，通知 AI 服务异步处理

**依赖**（pom.xml 补充）：

```xml
<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-amqp</artifactId>
    </dependency>
    <dependency>
        <groupId>io.minio</groupId>
        <artifactId>minio</artifactId>
        <version>8.5.7</version>
    </dependency>
</dependencies>
```

**核心代码**（Controller + Service，实际实现见 media 模块 `LectureController` / `LectureServiceImpl`）：

```java
@RestController
@RequestMapping("/api/lecture")
public class LectureController {

    @Resource private LectureService lectureService;

    /** 教学机构端上传讲义 */
    @PostMapping("/upload")
    public Result<Long> upload(
            @RequestParam("courseId") Long courseId,
            @RequestParam("file") MultipartFile file) {
        return Result.success(lectureService.uploadAndNotify(courseId, file));
    }
}
```

**讲义解析状态表**（实际实现：`xcplus_media.lecture_parse_status`）：

| 字段 | 说明 |
|---|---|
| id | 主键 |
| file_id | 文件标识（唯一，回调依据） |
| course_id / course_name | 所属课程 |
| status | processing / success / failed |
| message | 结果说明（如"解析成功，切片 N 条"） |
| update_time | 更新时间（Asia/Shanghai） |

## 3. 讲义解析状态回调接口

AI 服务处理完讲义后回调本接口，教学机构端据此展示解析状态、支持重新上传。

```java
@RestController
@RequestMapping("/api/lecture")
public class LectureCallbackController {

    @Resource private LectureService lectureService;

    /** AI 服务处理完成后的状态回调 */
    @PostMapping("/parse-status")
    public Result<Void> parseStatus(@RequestBody ParseStatusDTO dto) {
        lectureService.updateStatusByFileId(dto.getFileId(), dto.getStatus(), dto.getMessage());
        return Result.success();
    }

    @Data
    public static class ParseStatusDTO {
        private String fileId;     // 讲义文件标识
        private String status;     // success / failed
        private String message;    // 结果说明（失败原因）
    }
}
```

**查询接口（教学机构端轮询用）**：

```java
/** 按课程查询讲义解析状态列表（courseId 可空） */
@GetMapping("/parse-status/list")
public Result<List<LectureParseStatus>> list(@RequestParam(required = false) String courseId) {
    return Result.success(lectureService.listByCourse(courseId));
}

/** 单条查询 */
@GetMapping("/parse-status/{fileId}")
public Result<LectureParseStatus> get(@PathVariable String fileId) {
    return Result.success(lectureService.getByFileId(fileId));
}
```

> agent 侧提供同路径转发路由（`/api/lecture/*` → media-api），供统一入口使用。

## 4. 课程信息查询接口（AI Agent 推荐用）

AI 服务的课程推荐工具调用**门户已有的公开课程列表接口**。若现有接口返回结构
不同，可新增一个轻量查询接口（只读）：

```java
@RestController
@RequestMapping("/api/course")
public class CourseQueryController {

    @Resource private CourseService courseService;

    /** 公开课程列表（AI 推荐用，无需登录） */
    @GetMapping("/list")
    public Result<List<CourseVO>> list(@RequestParam(required = false) String keyword) {
        return Result.success(courseService.listPublic(keyword));
    }

    @Data
    public static class CourseVO {
        private Long id;
        private String name;      // 课程名称
        private String intro;     // 简介
        private String cover;     // 封面图URL
        private String url;       // 详情页URL（或由 AI 服务按模板拼接）
    }
}
```

AI 侧配置：`JAVA_BASE_URL=http://<门户后端地址>`，`COURSE_LIST_PATH=/api/course/list`。
课程卡片跳转：优先使用接口返回的 `url`；否则按 `JAVA_COURSE_DETAIL_URL_TEMPLATE`
（如 `http://<门户前端>/course/detail/{id}`）拼接。

## 5. 我的课程查询接口（AI Agent 工具用，需登录）

AI 助手的"我的课程"工具通过**网关**调用 learning 服务接口，**agent 原样透传用户请求携带的 JWT**：

- 路径：`GET /learning/mycoursetable`（经网关 63010）
- 鉴权：网关校验 JWT，learning 服务从 SecurityContext 解析用户
- 返回：`PageResult`，兼容 `records / items / list / data` 多种字段形态（agent 侧已做兼容）

> 无需 Java 侧新增接口——learning 服务已有该接口，agent 只做网关转发 + 结果兼容。

## 6. Agent 侧技术要点（对接时了解即可）

- **服务形态**：FastAPI + LangChain 1.x（LangGraph `create_agent` + `astream_events` v3 流式），独立部署端口 8000，聊天前端内置（`/`）
- **鉴权**：所有 `/api/*`（除 `/api/health`）要求 `Authorization: Bearer <JWT>`；token 缺失/过期/签名无效返回 401，前端跳回门户登录
- **工具调用闭环**：模型输出 tool_call（结构化 args）→ LangGraph 自动执行工具 → ToolMessage 回传 → 模型组织最终回答，全程 SSE 流式输出（thinking / answer / sources / courses / done 事件，15s 心跳）
- **课程卡片**：找课命中时 `courses` 事件携带 `{id, name, cover, url, price}`，前端渲染为可点击卡片；历史会话重开可重新渲染（卡片已持久化到 `chat_history.courses`）
- **讲义消费**：串行（prefetch=1），日志关键字 `收到讲义任务` / `讲义入库完成` / `回调成功`

## 7. 配置核对清单（上线前）

| 项 | 两端必须一致 |
|---|---|
| JWT 密钥 / 算法 | Java `JWT_SECRET` = AI `.env` `JWT_SECRET`，均 HS256 |
| RabbitMQ 地址/账号/vhost | 交换机 `xc.lecture`、路由键 `lecture.upload`、队列 `xc.lecture.parse` |
| MinIO 地址/bucket | `192.168.101.65:9000`，bucket `lecture` |
| 回调地址 | AI `.env` `JAVA_BASE_URL` + `LECTURE_CALLBACK_PATH=/api/lecture/parse-status` 与 Java 路由一致 |
| 课程列表接口 | AI `.env` `COURSE_LIST_PATH` 与 Java 路由一致 |

## 8. 联调步骤

1. 先启动 AI 服务（`uvicorn app.main:app --port 8000`），观察启动日志 `RAG向量库就绪` / `Agent就绪` / `开始监听讲义队列`
2. Java 侧调用讲义上传接口 → 观察 AI 服务日志出现 `收到讲义任务 … 讲义入库完成`
3. 查询 `lecture_parse_status` 表：status 应更新为 success；上传损坏文件可验证 failed
4. 教学机构端讲义管理页 → 上传 PDF → 观察轮询展示"解析中 → 解析成功"
5. 门户登录 → 点击"AI 学习助手" → 提问"我在学什么课？" → 验证工具调用返回真实选课列表
6. 提问"推荐一门课" → 验证回答下方出现可点击课程卡片，且正文无裸链接
